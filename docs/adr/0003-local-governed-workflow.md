# ADR-0003：以受控本地流程实现垂类系统

日期：2026-11-15。状态：实现并通过本地流程验证；真实模型和生产环境未验证。

问题：已有课程与关键词脚本不能满足用户对系统配置流程和逐板块实现的要求；缺乏准入、证据契约、模型边界、流程状态、审核与失效传播。

候选A：继续JSON+脚本手动串联，增加说明文档。实现简单，但无法可靠表达跨步骤检查点、修订与发布状态。

候选B：标准库SQLite+文件，增加小型确定性流程和可选模型选择接口，CLI写入、本机鉴权API只读。

候选C：云对象库+PostgreSQL+向量库+Agent编排+队列。当前没有规模/并发/真实模型收益证据，运维和权限复杂度过高。

选择B。用户明确先完成本地流程，预留云端/本地接口。实际小样本验证：14来源/32知识→证据→蓝图→Markdown/HTML/JSON；无证据阻断；测试样本覆盖人工审核→内部发布→撤回失效。具体结果以系统验收报告为准。

代价：单机可信写者；关键词非语义理解；全目录保守失效；审核身份依赖本机信任；没有OCR/ASR/视频/公网服务。状态门禁不等于操作系统安全或专业审核已完成。

迁移边界：SourceRevision、六项rights、知识来源坐标、EvidencePack、RequestSpec/Blueprint、Run/Artifact和review。可将SQLite替换事务服务、检索替换混合索引、导出替换媒体生产，但不得绕过源版本、外发及审核检查。

重新评估触发：多人在线写入、大量媒体异步任务、查询独立评测系统性失败、真实模型取得可量化质量净收益、公开运营条件落实。没有触发条件时保留本地最简实现。
