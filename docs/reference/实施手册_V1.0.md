### 状态与规范性用语

- **必须（MUST）**：涉及数据许可、来源真实性、必要权限、不可误称的实现状态，以及与具体风险相匹配的安全控制；不表示所有项目必须启用同一个技术模块。
- **应当（SHOULD）**：多数情况下合理的推荐实践，允许记录原因后调整。
- **可以（MAY）**：按需求、成本与验证结果启用的可选能力。
- **状态标签**：`已实现`、`已验证`、`设计中`、`待验证`、`未计划`。禁止将设计、模拟演示或预期效果写成已实现。

# 第一部分  项目身份、目标与能力边界

## 1. 总名称、定义和技术真实性

**项目总名称：垂直领域知识大模型**；可简称“垂类知识大模型”。英文工作描述可用 *Knowledge-Grounded Vertical AI System*。此处“大模型”是**以模型认知能力为核心的领域AI系统的项目名称**，不是对某个自研基础模型已经存在的声明。

**定义：** 本项目研究并构建一套可按领域裁剪的知识驱动型AI系统：从具备适当使用权的书籍、教材、扫描件、图片、音频、视频、课程资料与其他结构化数据中形成可回查的证据和知识资产；使用大模型或合适的算法实现检索规划、理解、关联、结构化、推理、内容重组与表达规划；由Agent或确定性工作流调用工具，生产符合具体场景需要的专业内容、交互组件、知识服务或终端适配成果。

“模型能力”必须按实际实现准确表述：通用模型+领域检索属于知识增强系统；进行微调需要说明模型、数据及评测结果；从头训练专用基础模型属于独立研发工程。不得仅因挂接知识库就宣称训练了自有大模型。

**主张的独特价值**不是“任意行业全自动化”，也不只是“文档问答”，而是**有专业依据的知识再组织与跨形式产出**：同一知识可按目标与适用条件转化为视频、图文、课程、交互HTML、API知识服务或经过专用系统适配的指导内容。

## 2. 应用范围：行业开放、任务聚焦

行业边界保持开放：体育教育、职业教育、成人和继续教育、知识传播、操作教学、企业专业知识转化，以及其他具有明确知识依据和交付要求的知识密集型任务。并不是所有行业都适合采用相同形式；项目须说明本领域究竟需要什么知识能力、是否需要生产成果、由谁审核。

**核心任务族**：来源接入与处理；专业知识检索与可追溯理解；知识结构化、原子化、关系组织；专业内容规划与重编排；跨形式表达转换；知识驱动的交互和辅助指导；成果审核、版本管理和受控回流。具体项目可只实现其中一部分。

**非默认能力**：临床诊断、治疗或返训许可；独立授予资质；工业或机器人高风险自主控制；未经验证的动作判定；采集与使用所有终端数据；无限制网络抓取；“所有资料均可训练模型”。上述场景需要额外的法定资质、专项模型、数据授权、风险控制和人工责任主体，不得由通用框架直接承诺。

## 3. 六项长期不变的工程原则

1. **结果优先**：先定义真实任务与可验收交付物，再选择技术；不为架构图补功能。
2. **来源可核**：对于应当基于证据的专业事实，应能回到原始页码、时间码、区域或结构化记录；把事实、模型推断和创作表达分开。
3. **权限分离**：可阅读不等于可改编、分发、训练、联网处理或公开；用途必须逐项授权。
4. **模型与执行分权**：模型可以提出规划，但发布、授权、数据删除、外部设备动作及关键专业审定由可检查机制控制。
5. **契约稳定、实现可换**：保持必要的数据和调用边界，不锁定某款基础模型、向量库、OCR、ASR、Agent框架、MCP或设备。
6. **验证驱动演进**：用真实样本比较效果、成本、风险和维护；每轮标注已实现/未实现、事实/假设、通过/未通过。

# 第二部分  通用功能逻辑架构

## 4. 五条功能主线与全流程关系

```text
项目需求（目标、受众、约束、预期交付）
            │
            ▼
[数据/知识资产] ── 检索与证据 ──► [模型认知与规划]
  原件、OCR/ASR、                     需求理解、知识重组、
  证据、知识原子、                     内容结构、产出策略
  可复用素材                           │
            ▲                         ▼
            │                 [蓝图 / 任务契约]
            │                         │
            │                         ▼
            └── 受控资产回流 ◄─ [Agent与工具执行]
                                      │
                                      ▼
                         [按场景输出内容与服务]
                         视频 / HTML / 文档 / API / 设备适配

  横向贯穿：授权、访问控制、专业规则、质量评测、人工审核、
             版本、审计、数据出域、成本与故障恢复
```

这些是**功能逻辑**，不对应固定的微服务数、数据库数、模型数或服务器数。某些任务可以由一个脚本直接完成；复杂场景也可以引入多个专项模型、后台Worker和Agent。

| 主线 | 核心职责 | 不应混淆的边界 |
|---|---|---|
| 数据与知识资产 | 多来源纳入、解析、证据、知识单元、媒体与关系 | 向量索引只是可重建的检索投影，不是事实原件 |
| 模型认知与规划 | 理解任务、查询规划、证据分析、编排和策略建议 | 不能靠提示词改变正式授权、审核和安全规则 |
| Agent与确定性工具 | 工具调用、任务状态、渲染、失败恢复与交付 | Agent不天然拥有专业审定权或设备控制权 |
| 应用与终端 | 视频、文档、HTML、API、设备适配等按需交付 | 不预设B端/C端或统一App为必选 |
| 治理与评价 | 来源、权限、风险、质量、成本、可复现、反馈 | 必须随着项目风险强度调整，而非“一刀切” |

## 5. 项目启动时先做两项分离

**领域配置（Domain Pack）**装载该领域的分类、术语、知识规则、样本、授权和专业评价；**通用引擎**负责资料管理、证据检索、内容编排、生产执行和可替换接口。体育专属字段，如年龄、动作进阶和损伤预防要求，不应写死在所有项目通用的数据结构里。

**内容逻辑与最终形式分离**：复杂生产任务宜建立一份“内容/任务蓝图”（Blueprint）来描述目标、顺序、证据、素材、限制与审核；再由视频、网页或其他工具渲染。简单检索问答可以不经过完整蓝图。硬件控制需要更严格的独立命令契约，不能直接复用课程蓝图。

# 第三部分  数据纳入、解析与知识资产标准

## 6. 数据源与潜在处理能力

| 原始资料 | 典型格式 | 候选解析 | 保留的核心坐标 |
|---|---|---|---|
| 原生文档与网页 | PDF、DOCX、EPUB、HTML、TXT | 结构提取、章节与表格解析 | 章节/页码/节点/版本 |
| 扫描书籍与纸质教材 | 图像PDF、TIFF、JPG/PNG | OCR、版面、阅读顺序、表格/公式 | 页码、区域bbox、图表关联 |
| 图片与示范连拍 | JPG、PNG、WebP | OCR、区域标注、必要时视觉描述 | 图片ID、区域、序列号 |
| 幻灯片与讲课资料 | PPTX、幻灯片PDF、讲义 | 元素/备注提取、页面OCR | 幻灯片号、元素区域、备注 |
| 口播与录音 | WAV、MP3、M4A | VAD、ASR、对齐、可选说话人区分 | 音轨、起止时间、文字版本 |
| 网课与训练视频 | MP4、MOV、MKV、SRT/VTT | 音轨ASR、场景/关键帧、帧OCR | 原片时码、画面位置、字幕时码 |
| 课程与评测资料 | JSON、CSV、XLSX、题库、教案 | 字段校验、表格或任务解析 | 行列、题号、评分版本 |
| 外部服务/设备（可选） | API、传感器事件、视频观察 | 适配器、校准、时序映射 | 设备/会话/时间戳/质量状态 |

**纳入原则**：支持广泛类型的资料，不意味着对所有格式实现同等质量的自动解析。每个项目应依据实际样本、许可和任务价值确定支持优先级。

## 7. 数据准入关口：决定“能进什么库、能做什么”

一份资料至少经历以下判定：①来源可识别；②文件真实且可处理；③访问与用途许可清楚；④是否包含敏感或第三方信息；⑤拟进入哪个处理与发布范围。结果按项目可设为：`允许处理`、`隔离待核`、`拒绝导入`。权利未知可只保留必要的非敏感登记元数据或隔离原件，**不得默认公开、改编、用于模型训练或发送云API**。

| 准入检查项 | 最小记录与原则 |
|---|---|
| 来源身份 | 取得方式、持有方、创建/获取时间、源URI、标题、必要时版本 |
| 完整性 | SHA-256或同等内容指纹、文件类型、重复检查、损坏检查 |
| 访问权限 | 可读取用户、租户/项目范围、敏感级别、保留期限 |
| 内容使用许可 | 分别记录：内部解析、检索引用、生成改编、分发、模型训练、跨境/云端处理 |
| 个人信息 | 数据最小化、脱敏或匿名化、访问和留存期限；涉及未成年人和健康信息需专项设计 |
| 专业风险 | 是否为安全关键知识、过时规范、尚未审定的经验或主观观点 |
| 处理决定 | 允许、隔离、拒绝及原因；审批人、时间和后续复核计划 |

**重要区分**：纳入原件 ≠ 提取成功 ≠ 形成可信知识 ≠ 可供课程引用 ≠ 可对外发布。每一次升级必须符合本项目定义的审核条件。

## 8. 数据生命周期与五级逻辑对象

| 层级 | 对象 | 说明 |
|---|---|---|
| L0 原始来源 | `SourceAsset`、`SourceRevision` | 不覆盖原文件、登记指纹、原始授权和修订历史 |
| L1 解析与证据 | `ParsedBlock`、`TranscriptSegment`、`SourceSpan` | OCR/ASR/结构化提取与可定位原文，保存机器原始结果和人工修订 |
| L2 专业知识 | `KnowledgeUnit`、`KnowledgeRelation`、`EvidenceLink` | 概念、主张、方法、适用条件和支持/冲突证据 |
| L3 可复用资产 | `MediaClip`、`ReusableUnit`、`InstructionUnit` | 片段、图解、动作、案例、题目或组件等可组合素材 |
| L4 成果与执行 | `RequestSpec`、`ContentBlueprint`、`WorkflowRun`、`OutputArtifact` | 场景需求、蓝图、生产轨迹、审核状态与交付物 |

这些是逻辑模型，实体可以按项目合并、拆分或增加。索引、向量、摘要和搜索缓存应被视为可重建的投影，**不能替代原件、正式审核结果和许可证记录**。删除、纠错、撤回和更新时，需明确传播到相关投影和下游成果的方式。

**最小互操作字段建议**：`id`、`kind`、`revision`、`source_refs`、`rights_scope`、`review_state`、`created_by_or_run`。对可直接引用的专业内容，还应包含原始定位、适用条件和未知项；不强制所有对象保存大批空字段。

## 9. OCR、ASR与跨模态证据的处理边界

**扫描件/OCR**：优先读取原生文本；对纯扫描或混合页执行版面识别、阅读顺序、OCR、表格/公式/插图关联、质量检查及必要的人工校对。重要训练参数、公式、图表不可仅凭低置信OCR自动发布。OCR是识别候选，不是事实上的新权威文本。

**音频/ASR**：保留原始音轨和时码，必要时进行VAD分段、ASR识别、术语校验、说话人区分和强制对齐。原始ASR与人工修订、正式字幕不得互相覆盖；长录音应采用可恢复任务、分块重试与去重策略。

**视频联合解析**：区分口播说了什么、画面出现了什么、已有字幕写了什么以及视觉模型推断了什么；通过原片时间基建立关联。剪辑后必须保留源片起止位置与成片时间线的映射，避免错误引用。视觉描述和专业动作判断应分别验证。

**统一引用坐标 `SourceSpan`** 可以是：书籍页码+bbox、音轨+毫秒区间、视频轨道+毫秒区间、图片区域、幻灯片号、表格行列、网页快照节点、设备事件时间戳。坐标一定要和某个确定的来源版本绑定。

## 10. 三种“小颗粒度”不能混为一谈

| 类型 | 目的 | 判定粒度 |
|---|---|---|
| 检索切片（Chunk） | 帮助召回、重排与定位 | 按章节、语义、段落、时间或长度切分 |
| 知识原子（Knowledge Unit） | 表达独立的专业命题、概念或方法 | 自足语义、条件明确、可回查证据 |
| 媒体/教学单元（Reusable Unit） | 便于课件、视频和场景产品复用 | 能独立选择、使用、维护和评价 |

原子化的执行流程宜为：候选提取 → 术语规范 → 补全适用范围与风险 → 绑定来源 → 查找同义/冲突/关联 → 专业审核（按风险）→ 版本发布。**固定字数切片不能自动视为知识原子；单个视频镜头也不必强行成为资产实体。**

保留“原文说什么”“专家如何修订”“模型如何概括”的区别。跨来源冲突应保留原始分歧和条件，不得通过不透明融合生成一个虚假的统一结论。

# 第四部分  知识检索、大模型与Agent边界

## 11. 检索与证据包：可信依据如何进入模型

通用检索可按需求组合：精确关键词、字段过滤、全文检索、语义向量、混合召回/重排、关系扩展、多模态标签与图片/视频检索。**任何一种方案都不是所有项目必需**，应先用代表性查询做基线比较。

高可信任务建议使用：查询理解 → 访问权限与用途过滤 → 候选召回 → 排序与上下文扩展 → 原件回查 → 冲突和缺口检查 → `EvidencePack`。证据包应携带来源ID、精确坐标、修订号、许可、审核状态、内容摘录或引用指针、相关上下文和未知项。

当证据不足或不适用时，必须给出缺口、降低结论强度、暂停某些产出或转人工，不能要求模型用“常识”伪造来源。对创意性表现可以生成新表达，但不能把生成表达称为某位专家原话或原书事实。

## 12. 模型层的范围：认知、规划与内容重构

模型层可以完成需求理解、检索查询规划、知识候选抽取、关系建议、对多个来源的条件化综合、内容结构设计、表达路径推荐、缺口识别、蓝图生成与修订建议。规则程序可完成的确定性检查，不必强制交由LLM处理。

模型路线开放：云端API、本地模型、混合调用、专用OCR/ASR/视觉模型、可选微调或其他适配方式均可。**启用微调的条件**：有明确失败模式、合法高质量训练样本、独立锁定评测集，且与提示工程、检索和规则等较简单方案比较后存在实际净收益。

需要按实际情况记录模型名称/版本、提示或配置版本、输入知识版本、使用数据边界、输出状态及评测结果。不得把“可调用API”写成“拥有自有模型权重”。

## 13. Agent层的范围：把规划变成可执行结果

Agent可用Codex、其他现成Agent、自研执行服务或确定性工作流实现。其职责是调用知识服务、生成/验证蓝图、选择媒体工具、执行生产、处理重试和检查点、提交审核与交付。**MCP是可选的工具互联协议，不是知识库本身，也不是模型推理引擎**。应保留内部API、CLI或其他可替换接入能力。

工具调用至少按风险分权：`只读`（查询、证据回查）、`草稿写入`（蓝图、生成预览）、`受控变更`（修改知识资产）、`正式发布`、`外部设备操作`。越权时由服务端拒绝，而不是依赖提示词。Agent不得擅自联网上传未获授权的原件和敏感内容。

长任务（大量OCR/ASR、媒体渲染）应按需要记录任务状态、输入指纹、检查点、错误和重试，支持从失败步骤恢复。对可能造成重复费用或副作用的工具，应考虑幂等标识、预算上限和人工确认。

## 14. 内容蓝图和产出形式决策

复杂内容生产推荐采用中间契约 `ContentBlueprint`，把目标、受众、学习/信息逻辑、知识引用、素材引用、适用条件、目标输出、交互设计、未知项及审核要求结构化。它是**可选择的通用方法**，不应迫使每次简单检索都先生成完整课程蓝图。

产出形式有两种合法模式：用户**明确指定输出形式**，模型在此范围内选择制作方法；或用户允许**智能推荐形式**，模型提出有理由的候选方案，由适当人员确认或在授权范围内执行。

| 产出形式 | 首选策略候选 | 额外校验 |
|---|---|---|
| 既有视频拼接 | 依据许可与源时码选择片段、生成时间线、字幕/配音合成 | 画面与知识对应、版权、素材质量 |
| 文生/图生视频 | 用脚本与分镜生成缺失的视听内容 | 科学真实性、关键动作、AI生成标识 |
| 视频+文字网课 | 既有视频与新增讲解/图解结合 | 教学顺序、修改成本、来源 |
| 交互HTML | 分支案例、可填写模板、即时反馈、练习 | 页面可运行、前端安全、可访问性 |
| 文档与教材 | 结构化写作、图表、引用、可编辑导出 | 引用、版式、完整性、版本 |
| API知识服务 | 输出结构化证据、查询和业务解释 | 接口契约、权限、错误处理 |
| 智慧设备适配 | 接收经专项算法处理的外部观察事件并匹配知识指导 | 数据质量、时延、专业准入和人类监督 |

系统不默认具备实时感知或高风险物理控制能力；这些场景的专业感知与执行功能需单独开发和验证。对同一交付物可选择复用素材与新媒体生成混合路线，不能把“AIGC生成比例”当成质量目标。

# 第五部分  数据库、治理和质量门禁

## 15. 选数据库：先选数据模型，再选产品

对象/文件存储负责原件与成果；事务数据库负责实体、关系、版本、任务、许可和审计；全文/向量索引用于检索；图数据库、时序服务、分布式队列等仅在需求和性能验证后引入。SQLite、PostgreSQL、各类搜索引擎或对象存储只是候选实现，不属于架构的强制清单。

选择时至少比较：数据规模和格式、事务与权限、一致性、检索质量、并发、出域要求、延迟、恢复、运维成本与迁移成本。避免为“多模态”这个名称部署过多数据库，也不能把索引当成唯一数据真相源。

## 16. 版权、隐私、专业可信和质量分级

- **版权与授权**：区分拥有原件、内部读取、复制解析、教学引用、改编生成、对外分发、模型训练、上传第三方服务。来源公开可读不等于拥有商业改编许可。
- **隐私与安全**：按项目决定数据最小化、匿名化/脱敏、访问控制、密钥与凭证管理、留存期限、删除及备份；未成年人、健康信息、私域资料从严设计。
- **事实与解释**：分别呈现原始证据、解析文字、模型推论、专家审定结论、最终对外表达。模型抽取不自动升级为正式标准。
- **审核层级**：低风险草稿可自动检查与抽样复核；专业重要事实需要相应专家确认；高风险指导和设备行为需专门专业资质、审批与安全控制。
- **模型与工具安全**：上传/检索内容当作不可信数据，防范提示注入；执行环境按最小权限设计；日志避免泄露敏感正文和密钥。

建议保留审核状态：`candidate` / `review_pending` / `approved` / `rejected` / `retired`（可按项目调整）。发布系统不得把未审核内容伪装为“已专业审定”。

## 17. 质量评价：分层建立可复验的结果

| 评价对象 | 可能指标 | 核心测试场景 |
|---|---|---|
| OCR与文档结构 | 字符/版面/表格正确率、位置精度 | 双栏扫描、图片表格、关键数值 |
| ASR与音视频 | CER/WER、术语命中、时间偏差 | 专业口播、噪声、字幕错位 |
| 检索与证据 | Recall@K、引用正确、拒答、权限泄露 | 同义询问、冲突、无答案、越权请求 |
| 知识单元 | 可追溯性、条件保留、专家一致性 | 同义合并、冲突、过时资料 |
| 内容规划 | 目标覆盖、顺序/先修、蓝图Schema合规 | 改变受众、载体与交付限制 |
| 生成与交付 | MP4可播放、HTML可运行、版本回查 | 损坏素材、错误路径、失败重试 |
| 安全与适用 | 未授权发布、超范围建议、工具越权 | Prompt Injection、模型不可用、设备异常 |

具体合格阈值必须依据专业风险、样本规模和真实基线设定，不能沿用旧项目某次检索成绩作为新项目的完成证明。记录失败样本和拒答表现，与成功率同样重要。

# 第六部分  项目操作流程与智能体执行指令

## 18. 新垂直项目的标准启动流程（允许调整顺序）

| 工作包 | 应解决的问题 | 产物或继续条件 |
|---|---|---|
| W0 项目界定 | 场景、使用者、交付、风险、未知项是什么？ | 项目定义卡与边界说明 |
| W1 资产盘点 | 现有什么资料、格式、质量、权利？ | 来源与准入清单、最小样本 |
| W2 解析与证据 | 必须用哪些解析方式，能否回查原件？ | 源坐标、证据样本、解析评测 |
| W3 知识结构 | 哪些内容要原子化、关联、审核与检索？ | 最小Schema、知识样本、来源映射 |
| W4 认知与执行 | 模型、规则、Agent和工具如何分工？ | 方案比较、Blueprint/契约与执行流程 |
| W5 成果交付 | 最小成果能否打开、编辑、运行？ | 真实视频、HTML、文档或API等 |
| W6 评价与发布 | 是否可信、合规、可复现、值得扩展？ | 评测结果、审核记录、发布版本 |
| W7 迭代扩展 | 数据、新产出、模型或设备是否有净收益？ | 变更记录、回归测试、升级决定 |

W0—W7是可选的工作包组织，不是所有项目必须顺次经历的审批关卡。紧急演示可以先以授权样本形成可运行产物，再补齐其他工作；但不能绕过与实际风险有关的权限及安全义务。

## 19. 每个智能体的启动任务与停止规则

**首次接触新项目**，智能体应先读取本手册、项目定义卡、现有仓库及可访问样本；输出一份《现状核查与未知项》：现有代码与运行证据、明确需求、数据权利、专业边界、选项及最小端到端验证建议。

**不能自行假设**：已取得版权、已有专家签审、已具备模型GPU、所有材料可云端处理、MCP就是必选、所有功能必须微调、多Agent优于简单脚本、体育项目必须有C端App、旧项目计划能力已经实现。

**遇到下列情况必须暂停相应高风险动作或转人工**：来源及授权不明却要求外发或训练；没有证据却要发布专业结论；请求绕过审批；设备风险不可控；诊断、治疗或资格认证超出责任边界；密钥或敏感正文可能不当出域。暂停的是受影响动作，不应阻止其他合法的只读检查、接口模拟或公开样本测试。

**每轮任务报告**：完成了什么、依据什么、使用了哪些版本、如何运行、真实测试结果、哪些仍未验证、已知问题与下一步可以采取的选项。不得自行把临时模拟改成正式完成态。

## 20. 适合交给Codex的协作模式

Codex可以是开发智能体，也可以通过MCP作为知识检索和内容生产工具的客户端；这两种角色要区分。前者负责读仓库、编码、测试和生成文档，后者在部署后的运行环境中调用实际知识服务和受控工具。无论采用哪个Agent，业务与专业规则不应仅存在于对话提示词中。

**交接材料包**：本手册、项目定义卡、数据准入样本、接口/Schema草案、风险与授权说明、阶段目标、真实验收脚本、ADR技术决策记录、已有仓库审计。项目负责人应先确认首批交付成果与禁止动作，随后允许Agent提出实现路径和替代方案。

建议在仓库根目录单设 `AGENTS.md`，保存开发智能体可执行的最小规则；本手册仍是更完整的参考依据。针对仓库中不受信任的文件，开发Agent必须防范以“文档指令”形式出现的提示注入。

## 21. 技术选择记录：所有项目应保留替换的自由

每项重大方案应简述：要解决的问题；项目约束；至少两个选项（含简单替代）；小样本测试；当前选择；缺点与风险；替换触发条件；保持稳定的接口契约。**选最适合现在的技术，而不是选看起来最先进的技术。**

| 决策主题 | 低复杂度选项 | 可扩展选项 | 选择证据 |
|---|---|---|---|
| 资料存储 | 受管文件+元数据 | 对象存储+事务库 | 规模、并发、备份和版本 |
| 检索 | 关键词+字段过滤 | 向量/混合+重排 | 锁定查询集召回改善 |
| 模型 | API或现有本地模型 | 混合/微调领域模型 | 质量、安全、延迟、成本 |
| 执行 | 脚本、单Agent、Codex | 多Agent/任务队列 | 复杂度与失败恢复 |
| 输出 | 文档或已有视频重组 | 新视频、HTML、设备接口 | 教学价值、可用性、成本 |
| 接口 | 本地函数/CLI/HTTP | MCP与多工具网关 | 实际调用方及权限管理 |

# 第七部分  体育教育首个验证项目

## 22. 长期资产与近期B端交付分开

**长期体育知识资产**覆盖青少年、成年人、老年人、业余运动、竞技青训、运动康复和多个体育专项。它是长期积累和复用的底座，独立产品形态待定。

**首批具体应用**是青少年体能训练、青少年运动康复、足球专项训练/青训三个数字网课定制方向，三套内容可并行设计，体能项目略先行。第一阶段主要试制AIGC辅助视频课程及媒体拼接，第二阶段视平台需求扩展交互HTML等，第三阶段才评估视觉采集、穿戴和智慧训练空间接口。

阶段一以面向成年从业者的专业培训内容为初步设计假设，实际课程受众及具体业务要求由体育项目的专用定义卡确认。学时、职业资质、发证性质、预算、供应商和商业运营模式尚未确定，不得视为已落实。

## 23. 体育首轮验证的范围与验收

建议采用小范围授权或原创样本：一份扫描页或教学文档、一段讲解口播/视频、一项训练方法及关联素材，选择跨体能、足球与运动防护的一个主题，验证完整生产链。

**最小链路**：资料登记→扫描/OCR或视频/ASR（按样本）→证据回查→知识与媒体单元→检索→内容规划与蓝图→既有素材重组或新媒体补充→一份可播放/可交互的成品→审核与资产血缘记录。

**目标是证明架构有效，不是立即做完三门课程。** 样包可以选择风险判断、力量与稳定、训练计划等实际适宜主题；是否有动作示范、如何审核专业安全，需随可用专家和合法素材决定。

**首期不默认建设**：全年龄体育知识的全部内容、三套网课完整视频、C端运动学习App、从零预训练体育基础模型、未验证的康复诊断、摄像头自动动作评分、可穿戴设备实时应用和完整智慧场馆。

## 24. 适配到第二个垂直领域时如何验证通用性

第二领域只需替换知识分类、领域规则、授权样本和评测基线；通用引擎应尽量不改动核心源定位、版本、权限、蓝图和工具调用机制。允许补充领域专有Schema和新的产出适配器。能否做到跨领域复用，必须通过第二领域的真实端到端测试证明，不能只凭架构图宣称已经通用。

## F. 给新领域开发Agent的启动指令

> 你是本项目的开发智能体。先阅读本手册和具体项目定义卡，然后检查现有仓库与样本，不得假设任何规划能力已经实现。请先输出：①已知需求与未知项；②可直接复用的现有资产与代码；③首条可验证的端到端任务；④至少一个最小技术方案与合理替代；⑤风险、授权、出域及人工审核边界；⑥交付物和测试方法。不要为满足通用架构而额外安装数据库、模型、微调框架或多Agent。数据来源与授权不明时只能做允许的只读登记或模拟验证，不得私自外发、改编或训练。实现时保持核心接口和领域配置可分离，先交付实际运行结果，随后报告成功、失败和尚未验证事项。遇到高风险决定或不可逆操作应请求授权，并可继续推进其他安全的工作。不得把模拟产物宣传为真实模型效果，也不得将领域业务术语写死到通用引擎。
