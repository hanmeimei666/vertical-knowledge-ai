# B01 项目配置与运行边界

## 输入、输出和责任

输入为负责人确认的场景、受众、成果形式、专业风险和资料目录；输出为PROJECT_BRIEF、runtime.json、domain_rules.json和配置校验结果。领域负责人决定业务边界，开发人员配置路径和运行方式，模型不能修改这些字段。

本项目首期为成年教师/教练的青少年体能教研，已有48课时课程资产。默认生产单个主题草稿，不从一次关键词请求自动推导整门课程或个体处方。

## 配置分层

|层|文件|作用与约束|
|---|---|---|
|业务定义|PROJECT_BRIEF.md|用户目标、课程课时、未知项、责任主体|
|运行参数|config/runtime.json|目录、数据库、检索、模型、只读API、审核人|
|领域规则|config/domain_rules.json|受众、teaching_draft、排除短语、专业边界和版本|
|资产用途|admit的manifest→SQLite asset记录|每一资料分别授权；不由运行配置批量提权|
|进程秘密|环境变量|API密钥/服务token，不写进JSON、蓝图、Git或日志|
|开发规则|AGENTS.md|指导开发；不是运行时业务权限检查|

## runtime字段

|字段|当前值/范围|生效位置|
|---|---|---|
|schema_version|1|不匹配拒绝启动|
|domain|youth_conditioning|只作为领域标识，核心不写死足球/青训逻辑|
|knowledge_directory|knowledge/youth-conditioning|seed现有编辑资产|
|raw_directory|data/raw|只能从该目录内的受管文件准入|
|database|data/runtime/catalog.sqlite3|运行时真实目录、修订、任务、审计|
|output_directory|outputs/workflow|每run独立draft/release目录|
|rules_file|config/domain_rules.json|加载领域规则|
|reviewer|null|未配置不能审核；配置后由对应本机操作者执行|
|retrieval.limit|1–10，默认5|最多进入证据包的知识数量|
|retrieval.minimum_score|至少1，默认3|关键词召回阈值|
|model|见B05|默认extractive，无网络调用|
|service|见B08|固定127.0.0.1，端口1024–65535|

所有文件路径必须解析后仍位于项目内，含符号链接的实际目标也检查。配置在进程启动时读取；改配置需重启CLI/服务。配置和领域规则纳入任务指纹，因此更改后旧任务在受管读取时失效，应新建任务。审核人需在待审核版本生成前配置，防止临时更改责任人后沿用旧批准。

## RequestSpec

`start(goal, request_key)`生成`{goal,audience,kind}`。goal为1–2000字符；audience和kind由领域配置给定。key为1–80字符字母/数字/下划线/连字符，作为幂等键。同key同需求回同run，同key异需求报错。生产请求不接受任意工具、系统提示、发布身份或输出路径。

排除短语只做明确超范围请求的基础拦截，不是完整医学风险分类器。所有成果均保留成人教研限定和人工审核要求。

## 验收与扩展

运行`python scripts/workflow.py status`；非法路径、非本机服务地址、非法模型和不支持规则均拒绝。变更领域时新建知识目录、规则和运行配置，不复制引擎中的业务判断。第二领域复用尚未真实验证，不能仅凭配置分离宣称通用有效。
