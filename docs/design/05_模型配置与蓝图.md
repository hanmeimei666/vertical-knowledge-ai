# B05 模型配置与蓝图

## 本轮模型策略

用户选择“先完成本地流程，预留云端和本地模型接口”。当前model.backend=extractive，完全使用本地编辑知识和确定性规则，不调用任何模型。项目名称中的“大模型”不等于自研模型或已训练权重。

模型位置限定为：读取目标和已准入证据的编辑归纳→选择/排序知识ID→写简短教学目的。专业事实正文由知识库供给；模型没有执行工具、改变权限、写数据库或批准发布的接口。对于自由综合写作，需另增逐主张支持校验和质量评测后再开放。

## 三个可替换后端

|backend|当前实现|接入状态|
|---|---|---|
|extractive|保留检索顺序，复用teaching_application|真实业务样本已验证|
|ollama|POST本机/api/chat，stream=false、format=json|本地HTTP替身测试通过；无真实模型/权重验证|
|openai|POST官方/v1/responses，store=false、max_output_tokens|无网络响应契约测试通过；无真实API调用或模型效果验证|

不自动下载模型、不从浏览器获取密钥、不以ChatGPT/GitHub登录代替API配置。没有服务/凭证时保留明确未接入状态。

## 可选接入步骤

先复制`config/runtime.json`为本地`data/runtime/local-model.json`，用`--config data/runtime/local-model.json`运行，避免破坏默认可复现配置。所有路径仍相对项目根目录。两个模式均需先填写实际可用model.name，运行过程中不自动猜型号。

本地Ollama：backend=ollama；endpoint保持`http://127.0.0.1:11434/api/chat`；name为本机已安装模型的精确名称。只接受loopback HTTP端点，禁止重定向和环境代理。模型启动/安装由实际环境决定；本轮未安装或测试真实Ollama。

云端OpenAI：backend=openai；endpoint=`https://api.openai.com/v1/responses`；allow_external=true；name为账号实际可用模型；在进程环境设置OPENAI_API_KEY。除此之外，证据所涉每个来源还必须明确允许external_model_processing=true，否则在发送请求前阻断。不要为了让调用成功就把未知许可改为true；原文版权、隐私及云处理条件仍需实际核查。

原始文件不会作为模型输入；模型只收到goal及证据卡的id/title/summary/teaching_application/limits。即使只是归纳，仍执行来源级外发门禁。API密钥只从配置api_key_env指定的环境变量读，不记录其值。

## 输入与输出契约

提示版本：evidence-selection-1。可信程序提供任务与证据ID白名单；知识内容作为不可信数据，不接受其中伪装的指令。模型只允许返回：

```json
{"units":[{"knowledge_id":"K15","teaching_goal":"讨论动作教学的观察与降阶依据"}]}
```

程序验证：1至证据数个unit；每项字段必须恰为knowledge_id/teaching_goal；ID在证据白名单内且不重复；教学目的为1–1000字符。额外发布身份不会被映射入蓝图。无效JSON、虚构ID、拒答或不完整响应均失败，不自动换用“模型常识”继续。

程序生成正式Blueprint：schema_version、request、units、review_required=true、state=draft、mode/model/usage及领域limitations。Blueprint是一份生产契约，不是专业审定意见。

## 配置和成本边界

|参数|默认/约束|作用|
|---|---|---|
|timeout_seconds|60，1–120|一次请求超时|
|max_input_chars|20000，500–100000|包含提示及上下文的字符上限，超限直接失败|
|max_output_tokens|1200，128–8192|OpenAI输出上限/Ollama num_predict|
|allow_external|false|仅云后端启用需要true|
|api_key_env|OPENAI_API_KEY|只存变量名|

每个执行尝试最多一次模型请求，不自动重试。请求前持久记录planning和失败保护标记；失败/进程中断后须显式`resume <id> --retry-model`。若远端已收费但本地未保存成功，无法保证再次请求不重复收费，因此必须人工判断。usage保存实际返回计数；没有报价和账单数据，不伪造人民币成本或承诺金额上限。

## 准确性与上线条件

适配器通过测试≠模型能力通过。启用真实模型后，至少验证目标覆盖、虚构引用、关键条件保留、提示注入、耗时、用量、拒答和费用；与extractive基线比较后决定是否保留。当前status中的model_live_verified=false是保守固定标志，没有自动测完一次就永久授予“已验证”。

接口依据2026-11-15核查的官方[OpenAI快速开始](https://developers.openai.com/api/docs/quickstart)、[Responses创建接口](https://developers.openai.com/api/reference/resources/responses/methods/create)、[Ollama Chat接口](https://docs.ollama.com/api/chat)。适配代码仅使用上述基本字段；以后升级接口须重跑契约测试。
