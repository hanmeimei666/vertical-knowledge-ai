# B04 检索与证据包

## 运行流程与接口

`evidence(query,purpose)`：校验当前原件指纹→逐知识检查全部引用→仅保留admitted且允许retrieve与purpose的来源→中文双字片段/英文词召回→排序→截断→返回EvidencePack。purpose只允许retrieve或adapt。

`workflow.py search`和HTTP `/search`使用retrieve；生产run使用adapt，所以“能查到”不代表“能改编”。一张知识卡任意引用不合规即整卡不参与，不在过滤后只留下有利证据。

## 召回基线

中文连续片段拆为相邻双字，单个汉字保留；英文/数字按词；标题/标签匹配计3分，归纳匹配计1分，完整query出现在标题再加6分。默认至少3分，最多5卡，分数相同按ID排序，结果可重现。

该分数不代表概率、专业可信度或完整性。词面相关可能误召回，纯同义表达可能漏召回；无候选只说明此检索未找到证据，不等于世界上不存在答案。系统不自动联网补证据，也不以模型常识伪造引文。

## EvidencePack契约

```json
{
  "schema_version": 1,
  "status": "evidence_candidates",
  "method": "Chinese bigram / English keyword matching",
  "purpose": "adapt",
  "entries": [{
    "id": "K15", "revision": 1, "hash": "内容与状态指纹",
    "summary": "编辑归纳", "limits": "适用边界",
    "references": [{
      "source": "LOCAL-STANDARD", "locator": "B106.R9",
      "source_revision": 1, "source_hash": "资产记录指纹",
      "original_sha256": "原文件指纹",
      "rights": {"internal_parse":true,"retrieve":true,"adapt":true,"redistribute":false,"model_training":false,"external_model_processing":false},
      "verification": "native_docx_read", "professional_review": "pending"
    }]
  }],
  "gaps": ["未自动消解冲突", "专业审核待完成"]
}
```

实际输出还含title、score、tags、教学用法和来源URL。国际来源的verification沿用实际核查层级：全文、摘要、索引分别保留。包中是知识编辑归纳及源指针，不夹带整个原件、解析全文或密钥。

## 缺口与冲突

无候选→status=no_evidence；生产run进入blocked，蓝图/渲染/模型调用均不执行。有候选→保留limits和gaps，不能自动表示证据充分。跨来源矛盾当前仅保留每卡条件和引用，由审核人识别；自动冲突检测与证据强度分级仍是设计项。

## 评测和替换

`config/eval_queries.json`锁定版本、问题、expected_any、top_k和最低命中率；`evaluate.py`输出逐题命中、缺口、输入/题集指纹及报告。它测的是任一标注相关卡是否进入Top3（Hit@3），不是全量相关性标注后的Recall@3。本轮10条相关、2条无证据开发用例；不能用此小集断言泛化性能。

升级向量检索前，补充与知识标题不同的同义问题、冲突问题和权限矩阵；锁定独立评估集，比较关键词、向量、混合召回的质量、延迟、费用及维护成本。权限过滤和EvidencePack契约保持不变。不要通过降低门槛去掩盖已知失败。
