# B07 审核、内部发布、血缘与审计

## 权责

|动作|允许主体/接口|本轮约束|
|---|---|---|
|查询/回查|本机CLI或持token的本机API调用方|按来源检索权限过滤|
|导入/知识修订/草稿写入|受信任本机操作者CLI|资料权限、路径、契约与版本校验|
|专业审核|runtime.reviewer指定的真实审核人，通过本机CLI|默认null；模型和API不能批准|
|内部版本发布|本机操作者CLI|必须当前approved且产物哈希一致|
|公开发布|无可用接口|再分发授权未全确认时拒绝；即使允许也无公网托管实现|
|设备动作|无接口|未计划|

当前是单机原型，reviewer字符串绑定本机可信操作者约定，不是数字签名或完整身份认证。任何可修改配置、程序或SQLite的磁盘用户都可绕过逻辑门禁。多人上线必须增加独立身份、角色和服务端不可篡改审计，再开放写API；不能仅靠提示词或姓名字符串承诺生产级安全。

## 审核步骤

1. 项目负责人先确认真实专业审核人及责任，填写reviewer；配置变化需重启，并重新生成待审版本。
2. 审核人查看lesson.md/html、bundle中的原始引用、来源核查层级、知识限制及完整性。
3. 逐项确认目标/受众、专业事实、适用条件、安全边界、引用回查、表达/素材许可；审核不等于真实教学效果已经实证。
4. 在CLI记录approve/reject、真实身份和具体意见；当前只能审核draft_ready版本。
5. 批准后发布为内部版本；拒绝后保留记录，修订输入并以新key重建，不覆盖拒绝历史。

```powershell
# 实际课程目前没有指定审核人，以下仅说明流程，不应直接照填姓名执行
python scripts/workflow.py review <run-id> --reviewer '<真实已指定审核人>' --decision approve --note '<专业审核范围、结论及残留限制>'
python scripts/workflow.py publish <run-id>
python scripts/workflow.py artifact <run-id> bundle.json --release
```

review记录包含人、结论、意见、UTC时间及input_hash；蓝图仍是草稿生产契约，不能靠更改其中state来发布。release.bundle附review，页面标为“内部审核版本，不代表实证有效或允许公开分发”。正式公开发布另需资料再分发权、渠道、运营要求和专业责任主体。

## 失效传播

每次源/知识记录新增修订，当前实现保守失效已有非阻断任务。原件未经登记直接变化、配置/规则/实现代码变动，在get_run/artifact/review/publish时再次计算指纹，拒绝沿用旧结果。任务清单只是概要，状态读取以inspect/受管artifact的复核为准。

```powershell
python scripts/workflow.py withdraw S04 --reason '<实际撤回依据>'
```

上述会新增retired修订；后续检索过滤，旧成果受管获取被拒绝。seed不会重新启用已撤回资料；恢复必须显式重新admit并说明依据。不会把测试撤回操作用于实际项目库。

已导出到外部的静态副本无法远程收回。操作者需按run_id/source_refs通知其接收者并撤下旧版本；本轮未实现对外分发或通知系统，不自动给他人发消息。物理文件保留供审计，直接磁盘访问不属于应用受管读取。

## 审计与反馈回流

audit表保存记录修订、run状态变化和步骤清单；不写完整查询、解析全文、token或API密钥。任务表和asset正文含内部数据，因此整个SQLite仍须保护，不能因“审计不写正文”就公开数据库。

教研反馈先由人审核，再更新知识归纳或来源记录→revision+1→重新检索生产→重新审核。没有模型自动提权、自动将反馈当权威知识或自动训练。审计当前可由本机管理员改动，没有不可篡改签名保证；生产迁移时需独立审计存储和最小权限。

验收用fixture审核人测试批准、发布、拒绝、越权、篡改、撤回；真实课程保持待专业审核，不伪造签审。
