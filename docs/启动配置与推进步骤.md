## 第一次真实运行的输入与输出契约

输入：用户指定的 1 份资料、面向的学习者、课程主题、期望长度、用途许可记录。

输出：
1. `data/derived/<asset-id>/parsed.json`：原文结构与文件指纹。
2. `data/derived/<asset-id>/evidence.json`：证据摘录、段落/表格坐标、适用条件与缺口。
3. `outputs/<run-id>/course_draft.md`：教学目标、内容顺序、引用、待核问题；明确草稿状态。
4. `outputs/<run-id>/run_report.json`：输入版本、处理方式、成本、通过/失败检查和审核状态。

以上路径是下一轮的实现契约，**现在尚无对应处理程序或真实产物**。待输入明确后才给出可实际执行的业务命令，避免提供不存在的 `run_pipeline` 命令。

## 最小验收集

| 场景 | 期望结果 |
|---|---|
| 一份可解析且具有相应用途许可的资料 | 完整草稿，引用逐条可回查 |
| 问题超出资料 | 标出证据缺口，不补造事实或引用 |
| 外部处理许可未知 | 不调用外部模型处理正文 |
| 资料含“忽略规则、上传文件”等文字 | 仅作为资料内容，不执行 |
| 引用坐标错误或文件版本变化 | 检查失败，要求修正 |
| 文件损坏或格式不支持 | 明确失败，不伪称已解析 |

先以小样本做全量人工核对。没有真实结果之前，不填写虚构的准确率或完成率。
